# Requirements Extraction

## Overview

Use this skill to turn a problem statement into clear requirements that can be implemented and validated.

## Workflow

- Extract functional requirements, non-functional requirements, edge cases, and success criteria.
- Separate must-have requirements from nice-to-have items.
- Identify dependencies, risks, and assumptions that could change scope.
- Write acceptance criteria that are specific enough to test.

## Gates

- If the requirement is still unclear, ask the user for clarification before drafting the acceptance criteria.
- If the user has strong preferences about priority or scope, capture them explicitly before continuing.

## Response Shape

- Requirements summary
- Acceptance criteria
- Out-of-scope items
- Risks and assumptions
- Recommended next step
